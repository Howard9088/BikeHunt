# BikeHunt 全球骑行好价

> BikeHunt 是一个全球骑行商品信息聚合与比价网站。
> 我们只做“信息搬运 + 结构化整理 + 人民币比价 + 购买路径判断”，不参与交易。

创建时间：2026-10-14

项目目录：`E:\项目开发\BikeHunt`

---

## 1. 一句话定位

**用户只需要一张支持境外支付的中国信用卡，BikeHunt 帮他找到：这个商品在哪里能买、哪里更便宜、预计人民币要花多少钱。**

最终交易始终在第三方网站完成。

BikeHunt：
- 不收款
- 不代付
- 不代下单
- 不持有库存
- 不处理订单
- 不处理物流
- 不处理售后
- 不保存用户用于购物的银行卡信息

---

## 2. 核心使用逻辑

用户不需要先选网站。

正确流程是：

```
找商品
→ BikeHunt 搜索全球同款
→ 排除不能直邮中国的渠道
→ 核对商家支持的卡种和中国发卡限制（境外支付卡仍需银行实际授权）
→ 外币价格统一换算成人民币
→ 叠加已知运费与税费
→ 按预计总成本从低到高排序
→ 用户点击外链
→ 在第三方网站自行完成交易
```

**商品是入口，网站只是渠道。**

每个商品统一展示：

- 商品名称 / 品牌 / 型号
- 商品图片
- 原币价格
- 人民币参考价格

- 是否直邮中国
- 中国大陆发行信用卡是否可用

- 税费
- 预计人民币总成本
- 数据更新时间
- 第三方商品页面链接

人民币换算使用统一汇率快照，避免不同网站之间直接拿不同外币数字比较。

## 5. 排序原则

推荐渠道必须先满足：

1. **能直邮中国**
2. **有明确的国际卡种依据，且没有禁止中国发行卡的限制；实际支付仍需银行授权**
3. **商品可购买、有库存**

满足购买条件后，才按：

```
预计总成本 = 人民币商品价 + 国际运费 + 税费
```

从低到高排序。

如果运费或税费尚未核实，则明确标记“待确认”，不伪装成最终到手价。

## 7. 商业边界

BikeHunt 是**信息服务与导购导航**，不是商城。

可以做：
- 商品信息聚合
- 跨站比价
- 人民币换算
- 运费与税费估算
- 历史价格
- 降价提醒
- Affiliate 联盟链接 / 导购佣金（需清晰标注）

不做：
- 站内收款
- 站内购物车结算
- 代购代付
- 代下单
- 订单履约
- 清关代理
- 售后处理
- 自营库存

### 精选好价与普通商品搜索

- 默认「精选好价」仅保留最近一小时内核实有库存的当前实时报价：同一商家、同一规格、同一币种的商家原价必须高于正数现价。保留缓存、未知库存、售罄、过期报价及历史降价事件不会补成折扣。
- 卡片的商家原价、现价、折扣幅度、人民币商品参考价、尺码与颜色来自同一条报价。即使另一规格有更低的全价，或另一个渠道已售罄的报价有折扣，也不会混用。商品价不包含尚未核实的运费与税费。
- 尚未取得明确商家促销期限时显示「未取得折扣结束时间」；JSON-LD 的日期型 `price_valid_until` 只用于判断价格是否失效，不被用作限时活动或倒计时证明。
- 无符合条件的折扣时显示真实空状态。品牌和车队目录保留普通商品与过期参考记录，已确认全部售罄的商品仍不展示。全站输入搜索词后显示「搜索结果」，允许查找普通商品；品牌／车队中的搜索仍限定当前来源。清空全站搜索或点击「精选好价」恢复折扣筛选，后者同时清空搜索词。
- 折扣引用字段参与发布内容哈希，并校验到同一 `reference_offer_id` 和 `reference_variant_id`；状态心跳仅更新绑定报价的真实采集时间。页面时钟过期、价格有效期结束或采集失败时撤下精选资格。
- 回归：`node scripts/test_featured_deals.js`、`python -m unittest discover -s tests -p 'test_featured_deals.py'`。代码推送 CI 还运行 `python scripts/test_featured_deals_ui.py`，覆盖桌面、手机、小屏手机，以及普通商品搜索、Back／重载、来源范围和失效空状态。
