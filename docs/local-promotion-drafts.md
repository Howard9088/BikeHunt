# 本地促销待审包

这项功能只读取 BikeHunt 已有的本地报价、采集状态和事件记录，生成待人工复核的文案及证据包。它不联网、不登录社交账户、不下载商品图片、不发送消息、不发布、不添加推广追踪参数，也没有接入网站发布或 CI 自动上传流程。

## 使用

```sh
python scripts/prepare_promotion.py
```

首次运行只建立“从现在开始”的起点，输出 0 个候选是正常情况。后续在已有采集完成后再次运行，才检查起点之后的新事件。普通重复采集、仅更新时间、不变价，不会生成新的宣传包。

如确实要人工复核一段历史，必须同时明确起止时间，包含时区，且窗口不超过 7 天、结束时间不晚于运行时间：

```sh
python scripts/prepare_promotion.py \
  --since 2026-10-14T00:00:00+00:00 \
  --until 2026-10-15T00:00:00+00:00
```

这仍会检查当前报价和库存。指定历史窗口不解除证据、时效、来源健康或精确规格限制，也不会把没有旧状态的历史消息补成促销。

可用 `--root /path/to/BikeHunt` 指定完整项目根目录。输出位置固定为该根目录的 `storage/promotions/`，不能改到公开网站目录；拒绝通过 storage 符号链接跳到外部位置。

## 文件

- `storage/promotions/queue.sqlite3`：本地起点、稳定草稿标识和待审包记录
- `storage/promotions/queue.json`：所有草稿及本轮汇总
- `storage/promotions/last_run.json`：创建、更新、失效及跳过原因计数
- `storage/promotions/drafts/<稳定标识>/package.json`：逐尺码、逐事件的证据、时间及站内核对标识
- 同目录的 `draft.txt`：人工可读文案，明确标记“待人工复核；尚未发布”

整个 `storage/` 已被 `.gitignore` 排除；不要把这些包复制进 `_site/`、公开数据、GitHub Actions 制品或社交平台。它们只是草稿，生成不代表获准外发。发布前必须再次运行检查、人工查看商品原站，并另行获得所需的发送或发布授权。

若一次文件导出被中断，SQLite 是本地队列的依据；再次运行可以重新导出。请保留队列，不要删除起点来制造重复活动。

## 哪些事件有资格

- 真实降价：同一个报价 ID、来源、原站 URL、完整规格、市场及币种，旧金额与新金额都有有效采集证据，且新金额严格低于旧金额。
- 真实补货：旧库存明确为 `out_of_stock`，新库存为 `in_stock`。旧库存缺失或 `unknown` 不构成补货。若金额也下降，同一包同时标明降价和补货；不能因为事件类别叫 `price_changed` 就漏掉补货。
- 当前精确报价仍存在，当前价格与事件一致，仍明确有货。当前报价及来源采集核实均在 1 小时内，没有未来时间、过期价格、保留旧缓存或采集失败。
- 来源必须明确启用、采集状态 `success` 且无错误。本版保守地跳过整个 `partial` 来源，即使其中有部分页面成功；不把不完整采集当作推广依据。
- 旧、新市场必须分别有记录且相同。不能从今天的市场配置倒推旧市场，也不能因为币种相同就认定市场相同。
- 品牌、精确型号、颜色、尺码、来源和市场等必要资料缺失，会给出跳过原因。无法确认的商品图只留空，不用其他产品的图片替代。
- 商家链接必须来自该来源的配置域名，与原始和当前精确报价 URL 一致，且是安全 HTTPS 商品路径。拒绝凭据、IP/本地地址、首页、合集/搜索/结账/跳转页面，以及推广追踪参数。
- 排除初次发现、恢复的历史消息、已抑制消息、后续事件已取代的报价、币种切换和未知旧价格。不会从划线价、相似商品或另一市场拼出“降价”。

对于旧库存未知但价格变化证据完整的事件，可以生成“降价”，绝不会附加“补货”。

## 合并与复核

只把同一精确品牌型号/款式、颜色、来源、市场、币种、旧新价格变化及活动类型的尺码合并。同名、不同颜色、不同市场或不同价格变化不会合并。稳定标识不包含运行时间、采集时间或尺码，因此同一变化重复运行不会另排一条；随后确认的另一尺码会更新已有草稿。

每次运行也会重新核对已有草稿。新报价取代旧活动、售罄、来源失败或核实过期时，草稿会标为 `invalidated`，文案改为“已失效，勿发布”。`valid_until` 是本次库存证据的时效上限，不是商家保证保价或保证有货；离线文件不会自行更新，必须运行复核。

包中的 BikeHunt 链接是已知网站首页入口。`product_id` / `variant_id` 供精确核对，当前网站没有支持这些参数的商品深链，因此不虚构“直达本站商品”链接。原站商品页和可用的准确商品图 URL 单独保留。文案不声称最低价、免费配送、直邮可用、含税到手总价或支付一定成功。

## 事件数据库兼容

`UpdateStore` 对现有 SQLite 增加可空的 `old_stock`、`old_context_json` 和 `current_context_json`。迁移不重写历史、不移动事件 ID/游标、不补造旧状态。新采集只把实际上一条报价的库存写入 `old_stock`；首次发现为 NULL。

上下文保存当时的精确报价 ID、来源、商品 URL、完整规格、市场、币种金额、库存、采集时间和缓存状态，供本地校验。它们不导出到公共事件。公开事件的 `old_stock` 为可选字段，新的恢复流程能读取和恢复；旧种子没有这个字段时仍为 NULL。冷缓存恢复后的本地上下文仍为 NULL，即使公开行带有 `old_stock`，也不能推广，直到后续真实采集产生新的、完整的本地前后状态证据。

## 测试

```sh
python -m unittest discover -s tests -p 'test_promotion.py'
python -m unittest discover -s tests -p 'test_*.py'
```

测试在临时目录创建虚拟数据，覆盖首次起点、受限历史窗口、降价、补货、同时发生、旧状态未知、尺寸合并、不同币种/市场、最新事件取代、价格/库存变化、来源失败/部分失败、过期、重复运行、安全 URL、可空迁移及公开恢复。测试数据不进入实际活动队列。
