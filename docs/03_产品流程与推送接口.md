# BikeHunt 产品类型入口、中文海淘指引与更新推送

2026-10-14，依据用户本轮明确的产品流程实现。

## 用户流程

产品类型 → 精选好价（最新采集/价格更新）→ 同规格人民币比价 → 站内中文规则 → 分步海淘指引 → 原网站完成交易。

品牌与骑行车队作为辅助探索入口。默认上下手势一屏一件；平铺移入浏览设置。双击误放大受控，主动双指缩放保留。

## 模块与数据契约

| 模块 | Interface | 数据 |
| --- | --- | --- |
| 中文与类型 | `title_zh(name: str) -> str`、`category_of(name: str) -> str` | 英文原名、中文名称、类型代码；品牌/系列专名保留 |
| 规则库 | `capture(...) -> RuleDocument`、`translate(code, key, expected_hash, summary_zh) -> RuleBook` | 官方 URL、正文 hash、中文摘要、版本、核实时间、translated/changed/pending 状态 |
| 目录 | 品牌/车队查询 | 官网身份依据、商城状态、已采集报价数、规则完整性；未采集不冒充已接入 |
| 更新与推送 | `capture(previous: list[Offer], current: list[Offer]) -> list[dict]` | 新报价/价格变化区分、原币新旧金额、货币、库存、采集时间、事件 ID |
| 个人提醒 | 创建绑定二维码、查询扫码、按订阅分类发送 | 本地私有配置、匿名浏览器绑定、用户主动扫码、按事件去重、消息发送状态 |
| 个人筛选 | `ShopperProfile(gender, height_cm, weight_kg, chest_cm)`、`FitGuideService.assess(detail, profile) -> FitAssessment` | 全部/男/女、厘米/公斤，胸围为尺码表要求时的选填补充；偏好保存在浏览器，后端当前请求不持久化身体测量值 |
| 微信交流 | `Community.get()`、本机二维码配置 | 实际群二维码、标题、到期时间；过期隐藏，个人价格提醒另行绑定 |

规则正文不完整或抓取失败不覆盖有效中文摘要；原文改变后旧译文标记待复核。每天核对规则，变化时重新核实中文摘要。

服务运行时价格来源每 5 分钟核对一次。采集成功后价格或库存事件及时进入网站消息；网页打开时通过 SSE 更新。公开网站变化到被检测存在采集间隔，不能宣称上游无延迟。价格与规则任务串行，同类请求合并，不同类请求排队；关闭服务时取消后续排队。

个人微信使用用户选择的扫码绑定推送服务；未配置应用凭据、未绑定用户、未确认微信接收通道时不声称消息已送达。密钥放在 `config/`，不通过 `/data` 或公开接口输出。

## 当前页面与尺码规则

2026-10-14：四步图示依次为选规格、配送与仓库、人民币费用、原站下单。只显示有新鲜库存依据且有效期未结束的规格；颜色切换重置尺码，不把起价当作已选规格价格。

性别判断使用明确官方属性、商品名称或已核实的官网款式分区。服装性别未知时不强行判为男/女，非服装中性装备保留。身高/体重仅在官方尺码表提供相应范围时匹配，不能跨品牌套用一个经验公式。

`POST /api/fit/{product_id}` 输入 `ShopperProfile`，返回 `state`、`note_zh`、`candidate_sizes`、`required_measurements`、官方表及核查时间。当前维斯玛两款上衣按胸围对应现货；边界处保留可能重叠的范围，并要求用户自己选择最终规格。没有已核实尺码表时不给假定尺码。

车队排序采用 `data/team_ranking_2026.json` 的 UCI 官方日期快照；目录显示实际世界排名和日期，每队只呈现一个标志。数据口径为男子车队世界排名，当前页面仅列 18 支 WorldTeam，因此实际名次存在跳号。
