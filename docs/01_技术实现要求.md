## 0. 一句话定义

爬虫聚合全球骑行商品与价格 → 结构化归一 → 折算成人民币**到手价** → 用户在站内比价、下单、支付、收货。

网站的竞争力只有一句话：**同一个商品，我在这里看到的是"最终到手要花多少钱、多久能到、能不能付"**，而不是又一个商品列表页。

## 1. 范围与分期（先做什么，不做什么）

| 阶段 | 交付 | 是否碰钱 | 关键成功标准 |
| --- | --- | --- | --- |
| **M1 比价聚合** | 采集 → 归一 → 比价站（搜索/详情/到手价/降价提醒） | 不碰钱，跳转外站 | 数据准确、到手价可解释 |
| **M2 账号与交易** | 注册登录、实名、地址簿、购物车、下单、转运履约 | 收货款，代下单 | 订单可追踪、清关信息完整 |
| **M3 支付与规模化** | 国内收单、海外代付、自动清关、更多站点 | 全链路资金 | 对账平、退款可执行 |

一期**明确不做**：自营囤货、代垫资金、二手交易、竞价排名广告。避免在不具备资金与合规能力时把业务做重。

## 2. 技术选型（已拍板，不再摇摆）

| 层 | 选型 | 为什么 | 不要用 |
| --- | --- | --- | --- |
| 后端服务 | **Python 3.12 + FastAPI + Pydantic + SQLAlchemy 2.x** | 爬虫生态全在 Python，且本项目已归档 Scrapling，一套语言两种服务，人力最省 | 不要为了"前后端同构"把爬虫塞进 Node |
| 采集框架 | **Scrapling v0.4.15（已归档）+ Playwright（动态页）** | 归档版本已验证可用，省去选型 | 不要自研解析器 |
| 任务队列/调度 | **Celery + Redis + Celery Beat** | 分布式、重试、限频、优先级成熟 | 不要用裸 while 循环 + sleep |
| 主数据库 | **PostgreSQL 16** | 事务、JSONB、分区表（价格历史）都能扛 | 不要用 MySQL 存价格历史高频写入 |
| 缓存/限频 | **Redis** | 缓存 + 队列 + 令牌桶限频一个组件搞定 | —— |
| 搜索 | **Meilisearch**（前期）→ OpenSearch（规模后） | 中文分词与部署成本平衡最好 | 不要用 `LIKE '%…%'` 硬扛 |
| 前端 | **Next.js 15（App Router）+ TypeScript + Tailwind CSS** | 比价站命脉是 SEO，必须 SSR/ISR | 不要用纯 CSR 单页应用做首屏 |
| 图片 | **对象存储（S3 兼容）+ CDN，商品图转存自持** | 外链图片会被防盗链掐断，且是版权风险点 | 不要长期直接引用他站图片地址 |
| 汇率 | **人民币中间价（官方口径）+ 通道加价系数，缓存 1 小时** | 汇率波动直接影响毛利与纠纷 | 不要用免费汇率 API 当唯一来源 |
| 税费 | **自建规则引擎 + 外部税率表（可配置）** | 税则会变，不能硬编码 | 不要把税率写在代码里 |
| 部署 | **Docker Compose（单机起步）→ 云主机 + Nginx + CDN** | 起步要便宜，但必须能横向扩 | 不要一上来上 K8s |

## 3. 系统分层架构

自下而上五层，箭头方向 = 数据流向：

1. **外部依赖层**：海外站点 / 支付机构 / 承运与转运商 / 海关申报通道 / 汇率源
2. **采集层**：调度器 → 站点适配器（一站点一插件）→ 动态渲染 → 代理与限频 → 原始数据落盘
3. **数据与算法层**：清洗归一 → 商品对齐（同款去重）→ 汇率服务 / 税费规则引擎 / 到手价引擎 → 搜索索引 + 价格历史
4. **应用服务层**：认证 / 比价查询 / 购物车与订单 / 支付 / 清关与履约 / 通知与降价提醒
5. **用户端层**：首页 / 搜索与筛选 / 商品详情（多源报价对比）/ 降价提醒 / 结算 / 订单与物流 / 个人中心

**[必须]** 采集层与业务层数据库隔离：采集写入 `raw_*` 与 `stg_*`，只有清洗通过质检的数据才进 `core_*` 业务表。任何采集异常不得直接污染用户可见商品。

## 4. 数据模型（核心表）

**[必须]** 以下表在一期就必须建好，缺一不可：

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `site` | 目标站点主数据 | 域名、国家、币种、结账是否含 CNY、可用支付方式、是否直邮中国、税负方式（DDP/到岸/需转运）、采集策略、robots 状态 |
| `brand` | 品牌词典 | 标准名、别名、后续可用于假货与信誉风控 |
| `product` | 归一后商品（SPU） | 标准名、品牌、品类、型号、规格、目标人群（男/女/队版） |
| `variant` | 规格（SKU） | 尺码（EU/US/CM 标准化）、颜色、年份/赛季 |
| `offer` | 某站点某商品的报价 | site_id、外链 URL、原币价、促销价、库存状态、运费、抓取时间 |
| `price_history` | 价格时间序列（按月分区） | offer_id、价格、币种、采集时间 |
| `fx_rate` | 汇率快照 | 币种对、基准汇率、加价系数、生效时间 |
| `tax_rule` | 税费规则 | 品类/HS 归类、征税方式、税率、限值、生效区间、来源公告号 |
| `landed_cost` | 到手价计算结果 | offer_id、运费、税费、服务费、人民币到手价、计算时间、规则版本 |
| `user` / `user_identity` | 账号与实名 | 手机/邮箱、密码哈希、实名信息（**字段级加密**） |
| `address` | 地址簿 | 收货人、身份证（加密）、手机、地址、默认标记 |
| `cart` / `order` / `order_item` | 交易 | 状态机、快照价、锁汇汇率、报关要素 |
| `payment` | 支付流水 | 渠道、金额、状态、外部流水号、退款关联 |
| `shipment` / `customs` | 履约与清关 | 转运单号、国内单号、申报品名/价值/HS、清关状态 |
| `crawl_job` / `crawl_error` | 采集运维 | 站点、任务类型、耗时、成功率、错误原因 |

**[必须]** `offer` 与 `landed_cost` 必须记录"规则版本号 + 汇率快照 ID"，否则用户质疑价格时无法复盘。

## 5. 采集子系统技术要求

### 5.1 站点适配器规范（一站点一插件）
**[必须]** 每个站点一个独立适配器目录，只实现声明式配置 + 少量钩子，不得各写一套流程：

```
adapters/<site_code>/
├── config.yaml     # 站点元数据：币种、支付方式、是否直邮、税负方式、限频参数
├── list.yaml       # 列表页/搜索页入口、翻页规则、品类入口
├── detail.yaml     # 详情页字段抽取规则（选择器/正则）
└── hooks.py        # 仅当声明式规则无法覆盖时使用（登录态、签名、特殊翻页）
```

**[必须]** 新增一个站点，只允许改适配器目录，不允许改采集框架核心代码。

### 5.2 调度与限频
- **[必须]** 按站点配置并发与频率，默认单站 ≤1 请求/秒，遵守 robots 与站点条款；宁可慢，不封 IP。
- **[必须]** 任务支持优先级：价格监控 > 新品入库 > 全量补数。
- **[必须]** 失败重试有上限（默认 3 次，指数退避），超过即落 `crawl_error` 并告警，不静默丢弃。
- **[必须]** 支持断点续采：按品类/分页记录水位，中断后不从头重来。

### 5.3 字段抽取清单
| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 商品名、品牌、型号 | 必须 | 归一化输入 |
| 品类、子品类 | 必须 | 整车 / 配件 / 服装 / 队服 |
| 尺码、颜色、性别/队版 | 必须 | 转化为标准 SKU |
| 原币价、促销价、币种 | 必须 | 比价基础 |
| 库存状态 | 必须 | 售罄不下架，只标记 |
| 是否可发中国、运费政策 | 必须 | 直接决定该报价是否可用 |
| 结账是否支持 CNY、可用支付方式 | 必须 | 对应两条硬性准入标准 |
| 图片 URL | 必须 | 转存自持 |
| 素材/规格参数（重量、套件、轮组） | 建议 | 整车比价的关键 |

**[必须]** 拿不到"是否直邮/是否可付"的站点，该报价**不允许**进入用户可见列表。这是本项目与普通导购站的分界线。

### 5.4 归一化
- **[必须]** 品牌词典、品类树、尺码标准表三张基础表先行落地，采集端只做映射不做判断。
- **[必须]** 同款对齐规则（品牌 + 型号 + 年份 + 规格）可配置；对齐错误要有纠错入口。
- **[建议]** 多语言商品名统一转中文，保留原语言原文（便于比对）。

### 5.5 价格与变更
- **[必须]** 每次采集写入 `price_history`，保留价格曲线（降价提醒的基础）。
- **[必须]** 价格相对上次变动超过阈值时标记为"疑似促销/异常"，异常价格（如 100 倍偏差）不得直接展示。

### 5.6 质量校验（**[必须]**，不通过不进业务库）
字段完整率 ≥ 95%、价格在站点历史区间内、外链可访问、图片可下载、币种可识别。不达标进隔离区并告警。

### 5.7 合规底线（**[必须]**）
- 只采集公开可访问信息，不绕过登录、付费或授权；
- 记录来源 URL 与抓取时间，遵守站点条款与访问频率要求；
- 不采集用户账号、订单等隐私数据，不采集需登录才能看到的会员价；
- 商品图的使用须核对版权/授权边界，必要时以文字参数替代图片展示。

## 6. 到手价引擎（本项目最核心的一段代码）

```
人民币到手价 = 商品价 + 国际运费 + 进口税费 + 转运/合箱费 + 支付通道手续费 + 平台服务费
              ↑ 全部按同一汇率快照折算，并标注汇率时间
```

- **[必须]** 到手价必须"可展开"：每一项都能看到金额、口径和计算时间。不可展开的价格一律不许展示。
- **[必须]** 汇率口径：以官方人民币中间价为基准 + 通道加价系数，`fx_rate` 每 1 小时落库一次，订单结算时**锁定汇率快照**，结算后汇率波动由平台承担（须在服务条款中写明）。
- **[必须]** 税费规则引擎：按品类归入征税方式（跨境电商零售进口 / 个人物品行邮 / 一般贸易），税率与个人额度限值全部外部配置，标注来源公告；`待核定` 的税率一律不得上线展示，只能显示"税费待确认"。
- **[必须]** 排序优先按"到手价"，但必须提供"时效""是否可付""是否可直邮"三个筛选项，避免用户看到便宜但买不到的结果。
- **[建议]** 服务费规则独立可调（固定额 / 比例 / 阶梯），并可在后台按站点单独覆盖。

## 7. 注册与实名（一期后端预留，二期开放）

- **[必须]** 注册支持手机号 + 邮箱两种方式；密码用 **Argon2id** 哈希；登录支持二次验证。
- **[必须]** 实名信息（收货人姓名 + 身份证号）为清关必需，属敏感个人信息：字段级加密（AES-256-GCM + KMS 管理密钥）、界面脱敏展示、单独告知同意、可撤回与删除。
- **[必须]** 权限模型分三层：普通用户 / 客服（仅见脱敏信息与订单）/ 管理员（操作全审计日志）。
- **[必须]** 地址簿支持多收货人，清关信息与收货地址分开维护。

## 8. 支付与资金要求（合规红线）

- **M1 不碰钱**：只做跳转，钱走用户自己的卡，平台不接触资金。
- **[必须]** M3 收单必须通过持牌支付机构，平台不得自建资金池、不得代收代付、不得长期沉淀用户资金。
- **[必须]** 支持渠道：国内收单（微信 / 支付宝 / 银联，走持牌服务商）+ 海外代付（虚拟卡 / PayPal 等，视合规结论确定）。
- **[必须]** 支付与订单必须**三方对账**（订单 / 支付流水 / 渠道账单），日对账不平即告警。退款流程与时限必须可执行、可查询。
- **[必须]** 全额可退的边界写进服务条款：汇率已锁定、商品已下单、已入转运仓等状态下如何退款，必须先定义再开发。

## 9. 海淘履约要求

- **[必须]** 支持"海外仓地址 + 合箱/拆分"两种收货方式，运费与时效在结算前给出确定值。
- **[必须]** 报关要素（品名、价值、数量、HS 归类）由系统按商品归类生成，人工可修正，留痕。
- **[必须]** 物流轨迹对接：转运单号 → 国内单号映射，用户端可查；节点延误自动通知。
- **[必须]** 清关模式（跨境电商零售进口 / 个人物品行邮）在结算页展示，并说明税费由谁缴纳。

## 10. 网站（前端）要求

### 10.1 页面清单（**[必须]**）
| 页面 | 必需能力 |
| --- | --- |
| 首页 | 热门品类入口、近期降价、按"到手价"推荐 |
| 搜索/列表 | 关键词 + 品牌/品类/尺码/价格区间筛选、按到手价排序、**支付与直邮筛选** |
| 商品详情 | 同款多源报价对比表（站点 / 原价 / 运费 / 税费 / 到手价 / 时效 / 能否直邮）、到手价明细展开、价格曲线 |
| 降价提醒 | 订阅某 SKU 或某站点价格，触发邮件/短信 |
| 购物车与结算 | 锁汇率、算税费、展示总到手价、明确退款规则 |
| 订单与物流 | 状态机（待支付→已下单→已入库→清关中→派送中→已签收）、节点时间轴 |
| 个人中心 | 账号、实名、地址簿、订单、提醒设置 |

### 10.2 非功能（**[必须]**）
- SEO：SSR/ISR + sitemap + `schema.org/Product` 与 `Offer` 结构化数据（比价站的自然流量命脉）。
- 性能：列表与详情首屏 **LCP < 2.5s**，比价查询接口 **P95 < 500ms**。
- 兼容：**手机与电脑同等支持**，采用同一套响应式 Web；按移动优先设计核心交互，桌面端提高信息密度。iPhone/Android/桌面浏览器均需完整可用。
- 可用性：核心页面降级可用，采集侧故障不得导致站点 5xx。
- 一致性：同一 SKU 在不同页面的到手价必须同源（同一 `landed_cost` 记录），禁止各页面各算一遍。

## 11. 合规要求（**[必须]**，任何功能先过这一关）

| 事项 | 要求 |
| --- | --- |
| 数据采集 | 遵守 robots 与站点条款，记录来源与时间，可提供来源证明 |
| 个人信息 | 遵循个人信息保护法，最小必要、单独同意、加密存储、可删除 |
| 支付资金 | 持牌机构收单，不自建资金池，不做无牌代收代付 |
| 跨境税收 | 税则、税率、限额以官方现行公告为准，页面明示税费承担方 |
| 消费者权益 | 七天无理由、退款时限、延误赔付规则必须成文并展示 |
| 商品准入 | 整车/电池类（电助力）等涉准入与运输限制品类，先确认可运可清关再上架 |

## 13. 里程碑与验收标准

| 里程碑 | 内容 | 验收（不达标不算完成） |
| --- | --- | --- |
